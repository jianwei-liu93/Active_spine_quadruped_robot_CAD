# r11 copied-solid verifier contract

Implementation: `src/verify_link_sections_r11.py` (336 lines). Runtime CAD checks are **NOT_RUN** by the worker. Only syntax compilation and the pure pair enumeration check ran. No native document, FreeCAD session, source generator, schema, or previous r10 native was modified.

The lead calls `prepare(doc, baseline_doc, states=None, canonical=CANONICAL, expected_native_sha256=None)` on the FreeCAD GUI thread, with the already-open neutral `cad/flexor_r11_robot.FCStd` and `cad/flexor_r10_robot.FCStd`. There are no open, close, recompute, save, pose assignment, visibility assignment, or other document writes. Preparation copies physical placed shapes, used source shapes, initial placements, source identity/metadata, native Body/member states and sketch constraint counts. It computes read-only motion descriptors for the requested inputs. The returned dictionary contains no Document or document-object references. The lead must freeze/save the completed integration before supplying its final disk SHA; a full campaign without that explicit SHA cannot return `PASS_AFFECTED_1346_ONLY`.

Run `run(prepared, stop_on_collision=True, progress_path=None)` outside the GUI thread using those detached shapes/descriptors. `prove_identity(prepared)` and `section_screen(prepared)` can also run separately. The heavy run never calls a document API. The lead owns thread scheduling and all live/native integration. The report is returned in memory. If the lead explicitly supplies `progress_path`, it also atomically writes filesystem-only progress after each complete pose and at completion; it never writes a native document.

The affected IDs come from actual `PoseController.LinkSectionsR11`. Migration checks require 487 previous identities, 503 current identities, exactly 16 changed existing and 16 new, no retired physical instances, and four L3 plus four L4 bar instances. The verifier compares all 471 unaffected identities, source names, part numbers, numeric properties, source frames and placed neutral frames. Both source and placed solids use `verify_frame_revision_r09._strict_shape_identity`, including its strict adaptive fallback when exact BREP hashes differ. Compact proof digests avoid duplicating hundreds of geometry proof rows. Mechanism parameters and native stored pose must match exactly. Legacy MotionMap descriptors remain exact except the axial `y`/`length` fields of changed SyncB shafts and B retainers. Legacy bar maps must remain exact. The assembly config comparison permits only revision/limits text and the new r11 section subtree. Native r11 section parameters must equal the actual parameter JSON.

`affected_pairs(names, affected)` enumerates every unordered pair touching an affected identity exactly once: `k*n-k*(k+1)/2`, yielding **15,568** for 503 physical instances / 32 affected. Each pose first uses conservative transformed native AABBs or the existing r09 procedural generator bounds. Actual shapes are materialized lazily for candidates. Actual AABBs may further reject pairs; every remaining new geometry/placement pair receives an actual OCC common. Exact per-pair results are cached using both immutable native BREP/request digests and absolute placement matrices; cached overlaps are reported at every repeated input too. There are no group-based or approximate cache assumptions. Native solid validity is checked once; finite orthonormal determinant +1 transforms are checked each pose and mathematically preserve rigid-solid validity. Dynamic shapes remain generator-validated and explicitly screened when regenerated. No intended-contact exceptions exist. Nonfinite bounding boxes/volumes, negative common volumes, invalid nonempty commons, invalid/null/nonsingle solids, missing descriptor coverage and guide travel warnings fail. Every pose records its input hash, pair count, mutually exclusive bbox/new-OCC/exact-cache counts and ordered decision digest; collisions retain both physical IDs and measured volume. Springs and cables are regenerated using the existing `leg_motion_r07.regenerate_sources`, including its private cache/copy convention. Static world copies receive `pose * initial.inverse()`, dynamic local copies receive `pose`, preserving the existing adapter's transform convention.

Section probes inspect the four actual handed fork source contracts, both bearing-envelope bores and material points in main/added leaves. A long-bar midpoint probe checks retained floor material and the blind recess void. These are local geometric probes, not proof of manufacture, strength, fit, bearing retention, thrust sharing, or load capacity. Native Body/member validity and total/fully-constrained sketch counts are reported; changed sources must be native Bodies with sketches and no unconstrained sketches.

For the first screen, select unchanged state dictionaries from `manifest()['states']` covering neutral and critical configurations, then prepare only that bounded subset. The manifest delegates directly to `verify_changed_revision_r10.manifest`, preserving its exact 985 + 361 = 1,346 inputs. A successful subset is `PASS_BOUNDED_ONLY`. Run the full 1,346 only after final geometry and explicit lead SHA freeze; a successful complete affected-pair campaign is `PASS_AFFECTED_1346_ONLY`. Stop-on-collision defaults to true to avoid spending a full campaign on a failed candidate. Disable it only when the complete failure map is useful.

Preparation calls the existing r10 frozen-baseline validator and captures its entire dependency source list, the r08 motion dependency list, r11 modules/configs, baseline freeze file and exact original manifest file. Disk hashes for both native inputs and all those implementation/config dependencies are checked after screening. A lead collector must combine partition reports and require identical proof/manifest/pair/native/dependency digests, exact unique 1,346 sample/input coverage, exhaustive pair decision counts, unchanged disk/dependency guards and successful statuses; individual subsets retain bounded-only status. Capture fingerprints guard read-only preparation. The detached heavy job cannot observe edits to the live document after capture: it proves only its captured geometry. The lead must associate the saved frozen native with that capture and ensure no live integration occurs during preparation. Prior campaign reuse/acceptance, final native reopen/recompute/export, ground/interface AX, source-video fidelity, continuous clearance, loaded equilibrium and fabrication release remain separate lead gates. Changed-pair success alone does not establish a whole-robot PASS.
